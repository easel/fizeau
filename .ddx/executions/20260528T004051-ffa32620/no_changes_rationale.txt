PROBLEM ANALYSIS:
The bead requests moving 17 service_*.go files from root package to internal/serviceimpl. This creates a fundamental architectural challenge:

Files to move include:
- service_execute.go (defines 9 methods on root service struct)
- service_routing.go (defines 18 methods on root service struct)
- service_models.go, service_providers.go, and 13 others with similar coupling to root types

The challenge:
1. These files define methods on the root's "service" struct or heavily reference public types (ServiceExecuteRequest, RouteDecision, BillingModel, etc.)
2. Root's service.go imports internal/serviceimpl for serviceimpl.Runtime
3. Moving these files to internal/serviceimpl creates circular import: root → internal/serviceimpl → root

RECOMMENDED SOLUTION (per ADR-008 §2):
"If an implementation move exposes a cycle, the fix is to introduce smaller implementation-local interfaces or adapter functions, not to make the root package absorb implementation code again."

Phased approach:
1. Extract implementation logic from each of the 17 files into internal/serviceimpl functions that DON'T import root types (accept/return strings, []byte, or implementation-neutral types)
2. Keep minimal wrapper functions/methods in root that adapt public types to/from internal types
3. Delete files from root only after wrapping is complete
4. Update service_root_facade_allowlist_test.go (already modified to remove these 17 files)
5. Move white-box test files to internal/serviceimpl package_test.go

Pattern reference: See commit 5e6b833b (slice 1) - service_progress.go refactoring

WORK REQUIRED:
- 17 files × refactoring + wrapping + moving
- ~50+ test files moving/refactoring
- Validation that public API (FizeauService interface) remains unchanged
- Full test suite validation for no behavioral regressions

This is achievable but requires substantial careful refactoring to avoid breaking the public contract while achieving the internal boundary goal.
