    <title>fizeau: provider quota state machine + NoViableProviderForNow error</title>
    <description>
Introduce per-provider quota state (available -&gt; quota_exhausted -&gt; available) with retry_after timestamp. Routing engine excludes quota_exhausted providers from candidate selection. Define new typed error NoViableProviderForNow returned when Execute has zero eligible providers solely because all are quota_exhausted (i.e., would otherwise be available). Error carries retry_after timestamp (earliest expected provider recovery) and exhausted_providers []string. DDx (downstream) consumes this to pause its drain loop and resume on retry_after. This slice is the foundational plumbing — header parsing, burn-rate tracking, and probe behavior land in sibling beads. Reuses existing provider abstraction; no schema changes needed for state machine itself. Distinct from existing &#39;no-candidate&#39; / &#39;config&#39; errors and from the per-request transient feedback path (RecordRouteAttempt).
    </description>
    <acceptance>
1. Per-provider state machine with two states (available, quota_exhausted) and retry_after timestamp; explicit transition API. 2. Routing candidate selection excludes quota_exhausted providers whose retry_after is in the future. 3. NoViableProviderForNow typed error with retry_after time.Time and exhausted_providers []string fields, exported and errors.As-friendly. 4. Execute returns NoViableProviderForNow only when every otherwise-eligible provider is quota_exhausted (existing &#39;no-candidate&#39;/&#39;config&#39; errors unaffected). 5. Unit tests cover state transitions, candidate-selection exclusion, NoViableProviderForNow error shape and exposure of fields. 6. Existing tests pass.
