    <title>redesign: endpoint-first routing (kill named-provider profiles)</title>
    <description>
User-stated design direction (2026-04-21, DDx session). Current routing is built around named provider profiles (e.g. &#39;vidar-omlx&#39;, &#39;vidar-coder&#39;, &#39;bragi&#39;) each with a hard-coded model declaration. This breaks in multiple ugly ways and drove a zero-success drain of 32 test-migration beads on DDx:&#xA;&#xA;Failure 1: &#39;cheap: qwen/qwen3.6&#39; in .ddx/config.yaml routed to a DEAD vidar lmstudio endpoint (http://vidar:1234, 502 Bad Gateway) because the named profile declared its model as &#39;qwen3.5-27b&#39; and the request fuzzy-matched on that string before any liveness check ran.&#xA;&#xA;Failure 2: When failover hit vidar-omlx (http://vidar:1235), the request carried &#39;qwen3.5-27b&#39; as the model string — but vidar-omlx actually serves &#39;Qwen3.5-27B-4bit&#39; and &#39;Qwen3.6-35B-A3B-4bit&#39;. Every attempt 404&#39;d with &#39;Model not found&#39;.&#xA;&#xA;Failure 3: routing_smart.go already has NormalizeModelID (internal/provider/openai/discovery.go) doing case-insensitive + suffix match against a discovered catalog, but it is only wired in cmd/agent routing_smart.go — NOT in the Service.Execute path that every consumer (DDx, etc.) actually hits.&#xA;&#xA;Desired shape:&#xA;&#xA;1. Config = endpoint pairs, not named profiles:&#xA;   endpoints:&#xA;     - {type: lmstudio, host: vidar, port: 1234}&#xA;     - {type: omlx, host: vidar, port: 1235}&#xA;     - {type: lmstudio, host: bragi, port: 1234}&#xA;     - {type: openrouter, api_key: ...}&#xA;&#xA;2. On every dispatch, probe each endpoint&#39;s /v1/models with a short timeout. Skip endpoints that 502/timeout/empty.&#xA;&#xA;3. Build a live {endpoint, model_id} matrix from the probe. The model_id is whatever the server actually serves — no per-provider name hardcoding.&#xA;&#xA;4. Resolve the request (user asks for &#39;qwen3.6&#39; or any case-variant) against the matrix:&#xA;   - case-insensitive contains / suffix / prefix match against every live model_id&#xA;   - if multiple endpoints match, tie-break on prior performance (latency, success rate, cost) from the routing-metrics store&#xA;   - if one matches, use it&#xA;   - if none match, explicit error (&#39;no live endpoint offers a match for qwen3.6&#39;) + caller escalates&#xA;&#xA;5. Kill the named-profile config-block lookups in the routing hot path. User-facing aliases (labels) are fine as shorthand but resolve through the same discovery flow.&#xA;&#xA;6. NormalizeModelID&#39;s logic is the right primitive; extend and wire it into Service.Execute so every consumer benefits.
    </description>
    <acceptance>
(1) Config schema supports endpoint-only blocks (no per-provider &#39;name&#39; or &#39;model&#39; fields required). (2) Service.Execute (not just cmd/agent routing_smart.go) probes /v1/models and normalizes the requested model against live catalogs case-insensitively, including suffix/prefix variants (Qwen3.5-27B-4bit ↔ qwen3.5-27b, qwen/qwen3.6 ↔ Qwen3.6-35B-A3B-4bit). (3) Dead endpoints are skipped at probe time, not on the failing request. (4) When multiple live endpoints serve the same requested model, selection uses routing-metrics signals, not config ordering. (5) DDx&#39;s .ddx/config.yaml can express &#39;give me the best qwen3.6 you can find&#39; without naming vidar-omlx or any specific provider. (6) Integration test: with two endpoints A (dead) and B (live, serves Qwen3.6-35B-A3B-4bit), &#39;qwen3.6&#39; resolves to B without hand-holding. (7) Regression: no existing acceptance test regresses.
    </acceptance>
