    <title>Fix session logger close race for final override events</title>
    <description>
PROBLEM&#xA;A completed Fizeau/DDx run can print a warning after the agent succeeds:&#xA;&#xA;WARN session logger: write error err=&#34;write .ddx/agent-logs/svc-1778103547795097343.jsonl: file already closed&#34;&#xA;&#xA;The observed run completed its command_execution, created detached-HEAD commit 50ba08b, and produced a final response. The warning is post-run session-log persistence noise, but it can also mean a late routing-quality override event was not persisted to the per-session JSONL log. That weakens UsageReport/routing-quality reconstruction even though the user-visible execution succeeded.&#xA;&#xA;ROOT CAUSE WITH FILE:LINE&#xA;service_session_log.go:34 opens the service-owned session logger and service_session_log.go:91 writes terminal session.end events through the same logger. service_execute.go:423 defers final write/close from the runExecute goroutine and service_execute.go:436 closes the logger as soon as runExecute unwinds. service_taillog.go:153 handles final-event fanout and service_taillog.go:163 writes an override event to the same serviceSessionLog from the fanout goroutine immediately before forwarding the final event. That fanout write can race with runExecute closing the logger. internal/session/logger.go:93 closes the underlying file, but internal/session/logger.go:97-100 leaves l.file non-nil, so any late Write reaches internal/session/logger.go:85 and logs &#34;session logger: write error&#34; against a closed file.&#xA;&#xA;PROPOSED FIX&#xA;Make service session-log ownership deterministic so all session-log events that belong to an Execute call are persisted before the logger is closed. Prefer moving or synchronizing override-event persistence so the final-event fanout cannot write to a logger after runExecute closes it. Add a defensive logger close behavior only if it complements, rather than hides, the ordering fix: Logger.Close may set l.file nil after close, but the regression test must still prove the override event is persisted, not silently dropped.&#xA;&#xA;In-scope files:&#xA;- service_execute.go&#xA;- service_taillog.go&#xA;- service_session_log.go&#xA;- internal/session/logger.go&#xA;- focused tests in service_*_test.go and/or internal/session/logger_test.go&#xA;&#xA;NON-SCOPE&#xA;Do not change the public Execute event schema, harness-native stream parsers, benchmark matrix reporting, DDx CLI behavior, or TerminalBench/FHI logic. Do not suppress the warning without preserving the late override/routing-quality session-log event.&#xA;&#xA;PARENT AND DEPENDENCIES&#xA;Parent: fizeau-06524f43. Dependencies: none.
    </description>
